## FINAL DIAGNOSIS

### What is the FIRST point where our output differs from what the SDK expects?

**THE CRITICAL FAILURE POINT:**

```
[FORENSIC-GENERIC] GenericResolver.resolve() called
[FORENSIC-GENERIC] selected_indices=(0, 1)
[FORENSIC-GENERIC] minCount=2
[FORENSIC-GENERIC] maxCount=2
[FORENSIC-GENERIC] Returning (0,)
```

**The Error:**

GenericResolver receives:
- **Input**: `selected_indices=(0, 1)` - a tuple of TWO indices
- **Constraint**: `minCount=2, maxCount=2` - exactly TWO selections required
- **Output**: `(0,)` - only ONE index returned

**What the SDK expects**: `[0, 1]` (exactly 2 indices)  
**What we return**: `[0]` (only 1 index)

**Root Cause:**

GenericResolver.resolve() is returning ONLY THE FIRST INDEX from a multi-select action, discarding the second index. It treats all inputs as single-select, returning only `selected_indices[0]`.

The code does not preserve the full tuple when `len(selected_indices) > 1`.

## CONCLUSION

**The FIRST point where our output differs:**

**Location**: `GenericResolver.resolve()`  
**Input**: `selected_indices=(0, 1)` with `minCount=2, maxCount=2`  
**Expected output**: `(0, 1)`  
**Actual output**: `(0,)`  
**SDK consequence**: Rejects the response because returned list length (1) does not match minCount/maxCount (2)

**The bug**: GenericResolver discards multi-select indices and returns only the first one.
