def battle_select(select_list: list[int]) -> dict:

        raise ValueError("select_list is not list[int]")
    arg = (ctypes.c_int * len(select_list))(*select_list)  # Full list, one operation
    err = lib.Select(Battle.battle_ptr, arg, len(select_list))
    if err != 0:
        raise IndexError()

SOLUTION
================================================================================

Multi-Selection Support:

When minCount > 1 or maxCount > 1:
  1. ActionFactory generates combination actions
     For minCount=2, maxCount=2, 3 options:
     → [0,1], [0,2], [1,2] (3 actions)
  
  2. Agent selects one combination
     Chooses action 0 → [0, 1]
  
  3. Agent returns list of indices
     Returns: [0, 1]
  
  4. Wrapper passes through
     battle_select([0, 1])
  
  5. C++ validates
     len([0, 1]) = 2 >= minCount = 2 ✓
     len([0, 1]) = 2 <= maxCount = 2 ✓
  
  6. Validation succeeds

CONCLUSION
================================================================================

The INVALID status in Game 2 is caused by a **constraint violation** on 
multi-selection actions. The agent returned [0] instead of [0, 1] for a 
minCount=2, maxCount=2 context.

The fix is straightforward:
1. Generate multi-select combination actions when minCount/maxCount > 1
2. Agent returns list[int] instead of int for multi-select contexts
3. Wrapper passes list directly to battle_select()

All evidence from official SDK code confirms this protocol is correct.
