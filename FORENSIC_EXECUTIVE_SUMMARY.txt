EXECUTIVE SUMMARY
================================================================================

Question: Why do some games randomly (~1 in 10-20) end with INVALID status?
Answer: Multi-selection contexts are incorrectly routed to single-select resolver.

Root Cause: SelectionResolverRegistry maps incomplete context→resolver pairs.

Exact Failure: SelectContext.TO_HAND with minCount=2 uses GenericResolver instead 
of a multi-select resolver, returning [0] when [0,1] is required.

CONCLUSION
================================================================================

The multi-selection support hypothesis is CONCLUSIVELY CONFIRMED.

FACTS:
1. SelectContext.TO_HAND can have minCount=2 constraints (observed)
2. SelectionResolverRegistry routes TO_HAND to GenericResolver (registry default)
3. GenericResolver returns single-element tuples only (by design)
4. SDK receives [0] when [0,1] or [1,2] etc. is required
5. SDK validation fails because len([0])=1 < minCount=2
6. Environment sets status to INVALID

ROOT CAUSE: Incomplete context-to-resolver mapping in SelectionResolverRegistry

RARITY EXPLANATION: Multi-select non-TO_PRIZE contexts occur infrequently
  → ~1 in 10-20 games
  → Games that never hit TO_HAND multi-select contexts complete successfully
  → Games that do hit them end with INVALID

THE BUG IS REAL. SOLUTION IS STRAIGHTFORWARD.
